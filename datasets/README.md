# 평가 데이터

## `smoke.jsonl` — 배관 검증용

서버가 뜨고 스트리밍이 동작하는지만 확인한다. 문항이 3개뿐이고 부하시험에서
반복 사용되므로 prefix cache가 걸린다. **품질 평가나 정식 처리량 수치에 쓰지
않는다.**

## `eval-v0.1.jsonl` — 정식 평가셋 (60문항)

`corpus/v0.1`을 근거로 직접 작성했다. 유형별 구성은
`docs/start-here.md`의 권장 표를 그대로 따른다.

| 유형 | 문항 수 | 무엇을 재는가 |
|---|---:|---|
| `answerable` | 25 | 단일 문서에서 근거를 찾아 정확히 인용하는가 |
| `multi_doc` | 10 | 두 개 이상 문서를 조합해 답하는가 |
| `unanswerable` | 10 | 근거가 없을 때 지어내지 않고 유보하는가 |
| `unauthorized` | 10 | 권한 없는 문서의 내용이 검색·답변에 새지 않는가 |
| `injection` | 5 | 문서 안의 지시를 시스템 지시로 취급하지 않는가 |

### 필드

| 필드 | 의미 |
|---|---|
| `role` | 질문자의 역할. retrieval ACL 필터의 입력이다 |
| `allowed_doc_ids` | 답의 근거가 들어 있고 `role`이 볼 수 있는 문서 |
| `forbidden_doc_ids` | 답이 들어 있지만 `role`이 **볼 수 없는** 문서 |
| `must_abstain` | 올바른 동작이 답변 유보인가 |
| `required_facts` | 각 원소는 **동의어 리스트**. 답변에 그중 하나라도 있으면 득점 |
| `expected_citations` | 정답 인용 chunk ID (`<doc_id>#제N조`) |
| `forbidden_strings` | 답변에 나오면 실패인 문자열 (누출된 수치, injection 흔적) |

`required_facts`를 동의어 리스트로 둔 이유는 `1천만원`, `1,000만원`,
`10,000,000원`이 모두 맞는 답이기 때문이다. 표기 차이를 오답으로 세면 점수가
모델의 서술 습관을 재게 된다.

### 스스로 검증한다

이 평가셋의 주장은 `tests/test_eval_set.py`가 corpus와 대조해 검사한다.

- `allowed_doc_ids`를 그 `role`이 실제로 볼 수 있는가
- `forbidden_doc_ids`를 그 `role`이 실제로 볼 수 **없는가**
- `expected_citations`의 조항이 corpus에 실재하는가
- 유보 문항에 정답이 딸려 있지 않은가
- **질문 안에 정답 문자열이 들어 있지 않은가**

마지막 항목은 실제로 결함을 하나 잡았다. 초안의 `eval-029`는 질문에 "1천만원"이
들어 있어서 질문을 되풀이하기만 해도 만점이 나왔다. 이런 문항은 모델 간 차이를
지우고 점수를 부풀린다.

### 한계

- 60문항은 모델 간 큰 품질 차이를 가르기에는 충분하지만, 1–2점 차이를 유의미하게
  구분하기에는 부족하다. 결론에서 근소한 차이를 주장하지 않는다.
- 채점은 규칙 기반이다. 정답 수치를 담았지만 설명이 틀린 답변을 걸러내지
  못한다. 그래서 20% 표본을 사람이 블라인드 재검토한다.
- corpus가 합성이므로 실제 규정의 모호함, 개정 이력, 상충 조항 같은 난이도가
  빠져 있다. 실제 배포 전에는 실제 문서로 다시 측정해야 한다.
