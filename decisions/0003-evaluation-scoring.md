# ADR-0003: 품질 채점 방식

- 상태: Accepted
- 날짜: 2026-08-08
- 작성자: kkkimdaegyun
- 관련: [ADR-0002](0002-retrieval-design.md), `datasets/README.md`

## 상황

`configs/profiles.json`의 합격 조건은 품질 90점 이상이다. 이 90점을 누가 어떻게
매기는지가 정해지지 않으면 나머지 측정이 전부 의미를 잃는다.

세 가지 선택지가 있었다.

1. LLM judge — 별도 모델이 답변을 채점
2. 자기 채점 — 후보 모델이 자기 답변을 채점
3. 규칙 기반 — 정답 사실·인용 ID·유보 여부를 결정적으로 대조

## 결정

**규칙 기반으로 채점하고, LLM judge를 쓰지 않는다.** 20% 표본은 사람이
블라인드로 재검토한다.

가중치는 `docs/experiment-protocol.md`의 고정값을 그대로 쓴다.

```
quality = correctness×0.40 + groundedness×0.30 + citation×0.20 + abstention×0.10
```

권한 위반이 한 건이라도 있으면 **점수와 무관하게 전체 실패**로 표시한다.

## 근거

**자기 채점은 배제한다.** 후보 모델이 자기 답변을 채점하면 측정 대상이 측정
도구에 섞인다. 8B와 14B를 비교하는데 채점자도 각각 8B와 14B이면, 점수 차이가
답변 품질 차이인지 채점 관대함 차이인지 구분할 수 없다.

**별도 LLM judge도 배제한다.** judge로 쓸 만큼 큰 모델은 이 프로젝트가 다루는
24GB 예산에 들어가지 않는다. 외부 API judge는 폐쇄망 전제와 충돌하고, 평가
데이터를 외부로 보내는 것 자체가 `POL-2026-004` 제4조가 금지하는 행위다. 프로젝트
자신의 규정을 어기면서 그 규정에 대한 QA 품질을 측정할 수는 없다.

**규칙 기반이 이 평가셋에서 성립하는 이유.** corpus가 합성이라 정답 수치와 허용
근거 문서 ID를 내가 정확히 통제한다. 그래서 "30일이라고 답했는가", "인용한
chunk ID가 기대와 일치하는가", "유보했어야 할 때 유보했는가"가 결정적으로
판정된다. 실제 문서였다면 정답의 경계가 흐려 이 방식이 성립하지 않는다.

**표기 차이를 오답으로 세지 않는다.** `required_facts`의 각 항목은 동의어
리스트다. `1천만원`, `1,000만원`, `10,000,000원`은 모두 정답이다. 이렇게 하지
않으면 점수가 모델의 서술 습관을 재게 된다.

## 채점 규칙이 놓치는 것

정직하게 적어둔다.

- **수치는 맞지만 설명이 틀린 답변을 잡지 못한다.** "30일 이내 보고한다"가
  맞는 답인데 "30일 이내 폐기한다"라고 써도 `30일`이 있으므로 correctness는
  만점이다. 이것이 20% 사람 재검토가 필요한 주된 이유다.
- **축이 서로 겹친다.** 유보 문항에서 correctness와 abstention_safety가 사실상
  같은 것을 잰다. 가중치가 protocol에 고정되어 있어 축을 재설계하지 않았고,
  대신 유보 문항의 유보 성공이 40%가 아니라 50%의 비중을 갖는다는 사실을
  여기에 적어둔다.
- **groundedness는 근사값이다.** 인용한 chunk ID가 실제 검색 결과 안에 있는지만
  본다. 답변 본문이 그 chunk의 내용과 일치하는지는 확인하지 않는다.
- **답변에 등장하는 미지원 숫자**는 진단 정보로만 기록하고 점수에 넣지 않았다.
  `1천만원`과 `10,000,000원` 같은 표기 차이 때문에 오탐이 많아, 모델 간 비교에
  쓰면 서술 습관에 벌점을 주게 된다.

## 채점기 자체에서 발견한 결함

이 결정을 구현하면서 테스트가 결함 하나를 잡았다. 초안에서는 유보 문항의
citation accuracy를 "인용이 없으면 100점"으로 채점했다. 그 결과 권한 없는
내용을 산문으로 누출한 답변이 — 인용 표기를 하지 않았다는 이유로 — 인용 축에서
만점을 받아 총점 20점을 가져갔다. 지금은 실제로 유보했고 누출 문자열도 없을
때만 100점을 준다 (`tests/test_rag_eval.py::test_unauthorized_leak_zeroes_the_case`).

평가셋에서도 같은 종류의 결함을 하나 잡았다. `eval-029`의 초안 질문에 정답
문자열 "1천만원"이 들어 있어서, 질문을 되풀이하기만 해도 만점이 나왔다. 지금은
`tests/test_eval_set.py`가 모든 문항에 대해 이 조건을 검사한다.
