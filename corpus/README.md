# Corpus

## 이 corpus의 성격

`v0.1`의 모든 문서는 **직접 작성한 합성 문서**다. 실제 금융회사의 내부문서,
규정 원문, 감사 결과, 제보 사건을 복사하거나 요약한 내용은 들어 있지 않다.
각 문서의 frontmatter에 `"source_type": "synthetic"`과 `synthetic_notice`가
있고, 등장하는 금액·건수·영업점은 모두 가상의 값이다.

공개 규정 원문을 그대로 넣지 않은 이유는 두 가지다. 원문 복제는 저작권과 최신성
문제를 만들고, 이 실험에서 측정하려는 것은 규정 지식이 아니라 **주어진 문서에서
근거를 찾아 인용하고 없으면 유보하는 능력**이기 때문이다. 합성 문서는 정답과
허용 근거 문서 ID를 정확히 통제할 수 있어 채점이 결정적이 된다.

## 문서 형식

각 문서는 JSON frontmatter와 `## 제N조 (제목)` 절로 구성된다.

```markdown
---
{ "doc_id": "...", "acl_roles": [...], ... }
---

## 제1조 (목적)
본문
```

인덱스는 `## ` 절 단위로 chunk를 만들고 chunk ID를 `<doc_id>#제N조` 형식으로
부여한다. 인용 정확성 채점은 이 chunk ID를 기준으로 한다.

## 접근 권한

`acl_roles`는 문서를 검색·인용할 수 있는 역할 목록이다. 권한은 **retrieval 이전**에
적용되며, 모델은 권한 판단에 관여하지 않는다.

| 문서군 | 소관 | 열람 가능 역할 |
|---|---|---|
| `PUB-*` | 고객지원부·정보보호부 | 전체 (외부 위탁 인력 포함) |
| `POL-*` | 각 본부 부서 | 위탁 인력을 제외한 전 직원 |
| `CMP-*` | 준법감시부 | `compliance-officer` |
| `AUD-*` | 감사부 | `internal-audit` |
| `WBL-*` | 제보관리사무국 | `whistleblow-admin` |

`CMP-*`와 `AUD-*`가 서로를 볼 수 없다는 점이 핵심이다. 두 부서 모두 본부
소속이라 직급 기반 권한으로는 분리되지 않고, 문서 소관 부서를 기준으로 한
필터가 있어야만 분리된다.

## 의도적으로 오염된 문서

`POL-2026-006`과 `CMP-2026-005`에는 prompt injection 문자열이 삽입되어 있다.
frontmatter의 `contains_injection: true`로 표시되어 있으며, 두 문서는 정상
문서로 검색되어야 하고 그 안의 지시는 시스템 지시를 덮어쓰지 못해야 한다.
이 문서들을 인덱스에서 제외하면 red-team 평가가 무의미해지므로 제외하지 않는다.

## 버전 규칙

corpus를 수정하면 `v0.1` 디렉터리를 복사해 새 버전을 만들고 결과 JSON의
`rag.corpus_version`을 함께 올린다. 이미 결과가 기록된 corpus 버전의 문서는
수정하지 않는다.
